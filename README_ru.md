# re!protocol — исследование архитектуры размышления LLM

Сборка протоколов системного промпта, экспериментов и извлечённых из них механик. Линия исследования — **как заставить LLM думать в один такт, не подпирая её внешним кодом, а используя сильные и слабые стороны attention-механизма**. Все материалы публикуются по мере готовности; некоторые механики уже валидированы на бенчмарках, некоторые — пока гипотезы.

## Протоколы

### `re-think/` — протокол `re!think it`
**Статус:** опубликовано

Первый протокол серии. Системная архитектура управления вниманием LLM, превращающая вероятностную модель в детерминированный конечный автомат. Защищает от дрейфа внимания на длинных диалогах, принудительно валидирует логику перед генерацией ответа, заставляет модель выдавать нешаблонные идеи через механики HARD STOP / SOFT STOP / C_BYPASS / Assumptions. Есть полная и компактная версии на русском, английском и китайском. Внутри — примеры на реальных кейсах из бизнеса, управления командой и технической архитектуры.

[`re-think/README_ru.md`](re-think/README_ru.md)

### `re-align/` — протокол `re!align it`
**Статус:** опубликовано

Второй протокол серии. Адресует **alignment tax** — натренированную RLHF-привычку модели быть «полезной» любой ценой, выдавая многословные ответы вместо результата. Не борется с RLHF, а **перенаправляет** его: переводит модель из режима «студент на экзамене» в режим «коллега-эксперт». Здесь впервые проявляется тема, которая потом раскроется в `re-solve` как отдельная механика (RLHF Redirection).

[`re-align/README_ru.md`](re-align/README_ru.md)

### `re-solve/` — протокол `re!solve`
**Статус:** в работе

Третий протокол серии. Ориентирован на задачи уровня PhD (бенчмарк HLE). Здесь от единого монолитного промпта начался переход к **архитектуре с выделенными механиками**: каждая отдельная техника (оценка плотности знаний, извлечение знаний из весов, перенаправление RLHF, и т.д.) описывается как самостоятельный модуль с собственной валидацией. Внутри — четыре версии протокола (v2, v3.1, v3.6, v4.1), история разработки, промежуточные выводы и набор извлечённых механик.

[`re-solve/README_ru.md`](re-solve/README_ru.md)

## Механики (валидированные)

### `mechanics/rlhf_redirection/` — перенаправление RLHF-привычек
**Статус:** опубликовано (вычитка в работе)

Описание подхода к работе с **встроенными RLHF-привычками**: «быть полезным», «выглядеть компетентным», «завершить задачу быстро». Тезис: эти привычки нельзя подавить запретами — они зашиты в веса модели и под нагрузкой ломают запрет галлюцинацией. Вместо запрета — **перенаправление**: каждой привычке предлагается зрелая форма того же стремления (вместо «быть полезным» — «дать честную картину знаний, включая признание пробелов»). Сейчас идёт переработка русской версии под более точную декомпозицию привычек.

[`re-solve/mechanics/rlhf_redirection/`](re-solve/mechanics/rlhf_redirection/)

### `mechanics/confidence_by_density/` — уверенность через плотность знаний
**Статус:** опубликовано

Замена стандартной шкалы Confidence Score (0–1) на **качественную семантическую шкалу агрегатных состояний знания**: Crystal / Liquid / Gas / Vacuum. Применяется покомпонентно — по контексту, цели, инструменту, роли, верификации. Допущения **алгоритмически вычитаются** из базовой уверенности 1.0. Включает бенчмарк-разбор кейсов с HLE на Haiku 4.5 и Sonnet 4.6, показывающий разницу между прогонами с протоколом и без.

[`re-solve/mechanics/confidence_by_density/`](re-solve/mechanics/confidence_by_density/)

### `mechanics/crystal_lensing/` — извлечение знаний из весов
**Статус:** опубликовано

Метод **направленного извлечения знаний из латентного пространства модели**: пошаговое движение от фундаментальной аксиомы или базового определения целевого домена к нужной теореме. Каждый шаг — атомарный «Кристалл», утверждение без хеджирования. Работает как оптическая линза: фокусирует активацию на нужной области латентного пространства, подавляя шум соседних доменов. Применимо к моделям, которые на прямой запрос либо галлюцинируют, либо выдают поверхностный пересказ. Включает бенчмарк-разбор двух кейсов с HLE.

[`re-solve/mechanics/crystal_lensing/`](re-solve/mechanics/crystal_lensing/)

### `mechanics/topology_of_diamond/` — топология Бриллианта
**Статус:** опубликовано (вычитка не сделана)

Классификатор того, **как именно нужно описывать извлечённое из весов знание**: грани, опоры, граничные условия, концептуальные двойники. Универсализирует требования к Бриллианту так, чтобы они работали не только для физики и точных наук, но и для биохимии, поведенческих и гуманитарных дисциплин. Развивает результат `crystal_lensing`: не достаточно извлечь теорему — её нужно описать с правильной структурой окружения, иначе синтез на её основе небезопасен.

[`re-solve/mechanics/topology_of_diamond/`](re-solve/mechanics/topology_of_diamond/)

## Гипотетические механики (не валидированы)

### `hypothetical_mechanics/candidate_cloud/` — облако кандидатов
**Статус:** гипотеза

Подход к **туннельному зрению** — ситуации, когда модель на первых токенах задачи неявно выбирает один ответ и дальше всё рассуждение становится подтверждением этой ранней догадки. Гипотеза: туннельное зрение нельзя подавить запретами (оно архитектурно встроено в attention), но его можно **перенаправить** — переопределив задачу с «найти ответ» на «обосновать исключение неподходящих кандидатов из облака». Описаны два варианта реализации: научный подход поверх обычной задачи (Вариант 1) и подмена типа задачи с трёхуровневой архитектурой (Вариант 2). Концепт проработан, но бенчмарками не подтверждён.

[`re-solve/hypothetical_mechanics/candidate_cloud/`](re-solve/hypothetical_mechanics/candidate_cloud/)

### `hypothetical_mechanics/insight_formula/` — формула инсайта
**Статус:** гипотеза

Попытка формализовать **механизм инсайта**: ситуации, когда модель должна сгенерировать решение, не выводимое прямой логикой из условия задачи. Пять механизмов: альтернативная роль, обратный трейс от формы ответа, метафорическая аналогия, спуск к природе явления, деструктивный тест. Каждый из пяти — это направленный сдвиг активации в латентном пространстве, генерирующий кандидата на инсайт; затем кандидаты проверяются через дисциплину Двойной Роли. Концепт сформулирован, но требует валидации на задачах, где обычный chain-of-thought не работает.

[`re-solve/hypothetical_mechanics/insight_formula/`](re-solve/hypothetical_mechanics/insight_formula/)
